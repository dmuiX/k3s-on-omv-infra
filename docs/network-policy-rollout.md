# Workload isolation: VSO first, Grafana second

Phase 1 adds **one native ingress + egress NetworkPolicy per workload**. Each is complete in `k3s-on-omv-live/infra/network-policies`, including site-specific addresses. Infra selects exactly one file in each owning Application. Do not put them in an already served raw directory or move DNS/API allows into a later sync wave: the first policy selecting a Pod can isolate it immediately.

## What changes on merge

1. Publish Live first. The current Applications do not serve the new directory. Keep the first-line `# +argocd:skip-file-rendering` directive on `grafana.yaml`.
2. **Infra merge activates VSO**, not Grafana. The root and children track `main` and auto-sync. Verify both published revisions and the directory filters before merge; a missing Live path can break Application manifest generation. The expected diff is `vault-secrets-operator/allow-vault-secrets-operator-controller` only. No chart values, Pod rolls, admission changes or namespace-wide denies are needed.
3. **After VSO acceptance**, a separate Live PR removes the directive from `grafana.yaml` and updates the Live stage assertion. Only `kube-prometheus-stack/grafana` becomes desired. Never combine these two activations. Review Argo's desired resource names, not an unfiltered YAML glob or a manual apply of the Live folder.

The Nov 19 pre-change inventory counted 48 Deployment/DaemonSet/StatefulSet templates: 5 selected both ways, 8 ingress only, 35 neither. Neither phase-one Deployment was selected. Holding the inventory fixed, VSO alone would make that **6/8/34**; after Grafana **7/8/33**. These are projected selector counts, **not** runtime enforcement measurements. Jobs (including credential provisioners), operator-created Pods and host-network exceptions need their own assessment.

## Peer and port inventory

Read-only inspection of `k3s-on-omv` matched the pinned chart templates to deployed Pod labels, Services, EndpointSlices, ServiceMonitors, probe configuration and the policy union. Exact addresses and tuple tests stay in Live. Rules that name Pods combine namespace and workload selectors in the **same** peer.

| Subject / direction | Allowed path and reason |
|---|---|
| Both, egress | Cluster DNS: kube-dns Service or `kube-system` CoreDNS Pods, UDP/TCP 53. Kubernetes API: only `default/kubernetes` Service TCP 443 **or** the two advertised IPv4 endpoint hosts TCP 6443. Not a Cartesian product; not a node subnet. VSO uses the API for watches, leases, TokenRequest, delivery and rollout updates; Grafana's provisioning sidecars watch via the API. |
| VSO, ingress | Both Prometheus replicas → controller `manager` HTTPS 8443 and ambient HBONE TCP 15008. The ServiceMonitor authenticates with the Prometheus ServiceAccount token. The chart skips server certificate verification. Ambient kubelet probe source → HTTP 8081 only (`/healthz`, `/readyz`). No admission Service or webhook pointed at VSO. |
| VSO, egress | Shared VaultConnection → `openbao-active` HTTP 8200 with STRICT mesh mTLS (15008); follow `openbao-active=true` server label through leader changes. No direct connection to consumer Pods or PostgreSQL. |
| Grafana, ingress | TLS terminates on the Istio gateway. Gateway Pods → Grafana Service 80 → Pod HTTP 3000; Prometheus → HTTP `/metrics` on the same Pod port. Allow 15008 only for those peers. Ambient kubelet probe source → HTTP `/api/health` on 3000 only. |
| Grafana, egress | `k3s-postgres-rw` primary TCP 5432 (`ssl_mode=disable`, STRICT ambient mTLS), Prometheus datasource HTTP 9090 and Alertmanager datasource HTTP 9093, plus HBONE to each peer. Alertmanager has zero replicas/endpoints; keep it that way. Dashboard and datasource sidecars reload over localhost. No configured Grafana HA peer list or renderer: no gossip 9094 or profiling 6060 grant. |

**Other end of each connection:** current gateway and Prometheus egress, CoreDNS ingress and datasource ingress are not isolated. OpenBao's server policy admits the VSO namespace on 8200/15008; CNPG's instance policy admits the monitoring namespace on 5432/15008. These existing receiver grants are broader than the new *sender* grants; they do not grant egress back to either subject. The OpenBao metrics authorization still applies. The Grafana provisioner has a different selector. No additional policy currently selects either subject. Do not change peer workloads or claim to have tightened their namespace grants. Reply traffic is stateful; no reverse ephemeral-port rules. HBONE is a tunnel, not an inner-port ACL; these L4 rules do not replace mesh or application authorization.

## Acceptance and rollback (attended, not executed)

- Before **each** activation recheck `default/kubernetes` Service and EndpointSlices, DNS IP/Pods, ready data endpoints, selectors, enrollment, probe SNAT and every selecting policy on both ends. Update Live for endpoint changes **before** cutover. Use a non-production equivalent to verify permitted DNS, API and app traffic and a denied wrong-peer/wrong-port connection. A green render does not prove K3s/Flannel rule ordering or ztunnel behavior. Do not probe unrelated tenants.
- VSO: compare the single controller's readiness/restarts, lease progress, both Prometheus replicas' authenticated VSO target and consumer Ready/refresh status to baseline. Require a **new** successful reconciliation; check delivery and rotation with an approved disposable consumer (status, resource version and adoption, never Secret contents). Stop on stale deliveries, probe/scrape failures or unexpected restarts.
- Grafana: before enabling, inventory DB-managed datasources, notification destinations, auth/plugins and renderer/HA configuration with the owner. External update checks are configured and will be blocked; accept that explicitly or disable them in a separately reviewed change. No public HTTPS escape hatch. Verify gateway login, a real Prometheus query, DB-backed state and dashboard/datasource sidecar refresh on both replicas, `/api/health` and both scrapers. Do not scale Alertmanager to demonstrate a query.
- If checks fail, **do not advance**. Revert the affected source (VSO) or restore the skip directive (Grafana); wait for Argo to stop desiring the object. `selfHeal: true` can recreate it while desired; `prune: false` means the revert alone does **not** remove it. Obtain approval for targeted removal of only the named phase-one policy in its namespace. Verify the previous policy union and repeat the functional checks. No global prune, workload restart, or temporary allow-all.

**Unchanged PostgreSQL baseline:** The paired Live policy has three egress rules: API Service TCP 443, API endpoints TCP 6443, and destination-unrestricted TCP 443 for Barman WAL uploads to R2. The HTTPS exception is not R2-only. Phase one neither changes these rules nor grants unrestricted TCP 6443.

Offline: run `python -m unittest discover -s tests -p 'test_workload_isolation.py' -v` in Live. In Infra, with the paired private Live checkout, PyYAML, Helm and exact cached charts, run `PYTHONPATH=tests PLATFORM_LIVE_REPO=../k3s-on-omv-live PLATFORM_CHART_AUDIT=<cache> python -m unittest test_phase_one_network test_postgres_api_network -v`. These check exact flows, discovery gates, rendered workload selection and existing receiver grants. No Secret reads, log dumps or deployment are part of these checks.

## Remaining inventory

1. **Argo and controllers.** Split server, repo-server, application controller, Redis and other components. Replace existing any-source server ingress rather than layering a narrower allow over it. Inventory UI/CLI, Radar, internal RPC, Redis, approved Git/Helm sources, Kubernetes API and webhooks. Test fetch/render/sync and admission with a representative resource. Treat cert-manager, Crossplane, CNPG, Barman and backup jobs as distinct subjects; test renewal, reconciliation and recovery paths in addition to readiness.
2. **Storage, DNS and mesh.** Separate Longhorn UI/OIDC proxy from manager, CSI, engine and replica data paths. Validate a disposable volume mount, remount and replica recovery before advancing. For CoreDNS verify cluster lookup, upstream forwarding and API access. For Istio separate gateway, istiod, CNI and ztunnel; test enrollment and TLS on a disposable workload on each node. Inventory `hostNetwork` separately: where the CNI cannot distinguish Pod from node traffic, use validated host controls or record a scoped exception instead of claiming Pod isolation.
3. **Close the inventory.** Map every remaining template, scheduled/one-shot job and operator-created workload to owner, ingress/egress decisions, acceptance evidence and exceptions with review dates. An existing TLS or authentication requirement is not a substitute for an egress decision.

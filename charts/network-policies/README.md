# Network policies

Small standalone Git-sourced Helm component for the demonstrated Stage 6.3 patterns. It renders only NetworkPolicies, with explicit names, namespace, selectors and policyTypes; no generated labels, hooks or implicit allow rules.

## Interface

All inputs are under `networkPolicies`:

- `namespace`: required destination namespace (independent of Helm release name).
- `defaultDeny`: optional `{name, podSelector, policyTypes}`. An explicit `{}` selector means namespace-wide isolation; use a workload selector for workload-only isolation. No ingress/egress rules are added.
- `policies`: named allow policies with explicit `podSelector` and `policyTypes`.
  - `annotations`: optional string map passed through unchanged. Radar's helper API policy uses Argo CD wave `-2`, before its wave `-1` Sync hook; the chart previously had no annotation input.
  - `dns: true`: namespace-only kube-system peer, UDP then TCP 53. No CoreDNS selector or API ports.
  - `openbao: true`: one peer requiring OpenBao namespace **AND** `app.kubernetes.io/name: openbao`, TCP 8200/15008. Not suitable for namespace-only consumers.
  - `gatewayIngress: {namespace, ports}`: namespace-only ingress peer with explicit TCP ports, including HBONE only when listed.
  - `extraIngress` / `extraEgress`: native NetworkPolicy rule arrays for real exceptions; each requires explicit nonempty ports. Omitted `from`/`to` intentionally permits all peers on those ports. These are reviewed escape hatches, not automatic Internet/LAN classification or a complete Kubernetes validation framework.

Ordering is gateway then extra ingress, and DNS then OpenBao then extra egress. No normalization of peer OR/AND or port arrays. Policy names must be unique. Schema/template checks reject missing selectors, empty allow selectors, missing namespace, empty/invalid gateway ports, unbounded-port exception rules, wrong rule direction and allowances outside their policyTypes. Supply exact selectors and review raw exceptions; Helm schema validation does not replace Kubernetes API validation.

## Consumers and migration proof

Radar is the first consumer, through one `charts/network-policies` Application source and Live `apps/radar/network-values.yml`. The old authored `radar/resources/network-policy.yaml` is removed from its Kustomization and retired. No source precedence override or duplicate owner is needed. The captured migration baseline remains immutable. This later network change replaces the workload's broad API rule with Live-owned Service `10.43.0.1:443` and endpoint `192.168.1.2`, `.5`, `.7` TCP 6443 rules and adds a matching-label API-only policy for `radar-credentials`. Namespace-wide denial, gateway ingress 9280/15008, DNS, Prometheus, PostgreSQL, **namespace-only** OpenBao, OIDC gateway, Argo and public HTTPS remain unchanged. Public HTTPS still permits every TCP 443 destination, including the API Service. The published Apps helper also retains its broad TCP 443/6443 policy: the additive Live policy cannot restrict it. See [API ownership and rollout blockers](../../docs/api-network-ownership.md). The stricter `openbao` shorthand is deliberately **not** used for Radar's namespace-only exception.

Audiobookshelf remains generated by its existing chart, including workload-only deny, namespace-gateway **OR** same-namespace configurator ingress, gateway/public egress and the configurator policy. Replacing these would add another Application source, ownership switch and conditional `allowHTTP` wiring without reducing its already-native chart interface. No second network generator/dependency is introduced. The shared DNS/OpenBao implementation is checked against its configurator's actual rules, proving the repeated patterns without changing its consumer. Gateway ports/target selectors remain explicit rather than a universal app preset.

Native mechanism evidence: [the pinned chart audit](../../docs/chart-native-capabilities-audit.md) records no native NetworkPolicy in Radar 1.17.0 and existing native policy generation in Audiobookshelf 0.1.0. Stage 6.3 authorizes this narrow component; this is not a generic Kubernetes-object generator. Other network consumers and OpenBao's specialized policies are deferred, not silently normalized. Routes, PDBs, OIDC and PostgreSQL resources are outside this chart.

## Offline checks

```sh
ruby charts/network-policies/tests/test_render.rb
helm lint charts/network-policies -f charts/network-policies/tests/fixtures/radar-values.yaml
```

For a direct old/new chart comparison, set `PREVIOUS_NETWORK_CHART` to an old chart checkout when running the Ruby tests. The regression renders fixture and coordinated Live inputs with their respective root keys and compares complete NetworkPolicy objects. Without that optional checkout, immutable baseline comparisons still run.

Fixtures capture **complete pre-migration NetworkPolicy objects only**, no Secret objects or private hostnames. Tests compare complete Radar objects using fixture values and explicitly apply the API-policy delta to that immutable baseline for actual Live values, full unchanged Audiobookshelf objects from its current chart/Live values, repeated DNS/OpenBao rule equality, namespace versus workload deny scope, OR/AND peers and invalid settings. The sibling Apps and Live checkouts are required. No cluster connections.
